# 第一阶段后端数据方案

## 一、目标
- 当前阶段只接入第一波最小必要数据，用于支持稳定币信息展示、DeFi 收益池展示、收益发现页和后续分配逻辑的数据基础。
- 技术路径固定为：`DefiLlama -> Cloudflare Workers / Cron -> D1 -> App API`。
- 第一阶段强调低复杂度、低成本、字段语义贴近上游 API，不提前做复杂业务聚合。

## 二、数据来源 API

### 1. 稳定币列表
- Provider：`DefiLlama`
- 地址：`https://stablecoins.llama.fi/stablecoins`
- 返回根结构：
  - `peggedAssets`
  - `chains`

### 根级 `chains` 说明
- 根级 `chains` 当前不是字符串数组，而是链信息对象数组。
- 当前阶段后端只消费 `peggedAssets[]` 中的稳定币数据，暂不使用根级 `chains` 做业务输出。

### 当前阶段使用字段
- 来自 `peggedAssets[]`
  - `id`
  - `name`
  - `symbol`
  - `gecko_id`
  - `price`
  - `chains`
  - `circulating`
  - `circulatingPrevDay`
  - `circulatingPrevWeek`
  - `circulatingPrevMonth`
  - `chainCirculating`
  - `pegMechanism`
  - `priceSource`
  - `pegType`

### 说明
- 当前列表接口的单个稳定币对象中，不直接使用 `mcap`。
- 当前阶段表达规模时，优先使用 `circulating.peggedUSD`。
- 业务字段命名先保持和 API 原始返回一致，不额外重命名。

### 2. DeFi 收益池列表
- Provider：`DefiLlama`
- 地址：`https://yields.llama.fi/pools`
- 返回根结构：
  - `status`
  - `data`

### 当前阶段使用字段
- 来自 `data[]`
  - `pool`
  - `project`
  - `chain`
  - `symbol`
  - `apy`
  - `tvlUsd`
  - `poolMeta`

### 说明
- `poolMeta` 可能为空。
- `apy`、`tvlUsd` 允许为空或为 `0`。
- 当前阶段在后端做最小清洗和空值兜底，不做复杂规则加工。

## 三、稳定币信息展示模型

### 1. 稳定币自身维度
- 用于回答：
  - 这是什么稳定币
  - 稳定机制是什么
  - 当前价格是否稳定
  - 当前总体规模如何
- 主要字段：
  - `name`
  - `symbol`
  - `price`
  - `circulating`
  - `pegMechanism`
  - `priceSource`
  - `pegType`

### 2. 链维度
- 用于回答：
  - 这个稳定币主要分布在哪些链
  - 哪条链占比最高
  - 是否存在单链集中
  - 哪条链更值得继续看收益池
- 主要字段：
  - `chains`
  - `chainCirculating`

### 3. 当前阶段结论
- 第一阶段后端和 API 设计默认支持这两个维度。
- 第一阶段只提供原始字段与最小清洗结果，不额外构造复杂业务视图。

## 四、Cloudflare 使用服务

### 当前必需
- `Workers`
  - 提供后端 API
  - 执行数据处理逻辑
- `Cron Triggers`
  - 定时同步 DefiLlama 数据
- `D1`
  - 存储 `stablecoins`、`yield_pools`、`sync_state`

### 后期可选
- `KV`
  - 用于榜单、聚合结果等短时缓存

## 五、后端依赖

### 必需
- `wrangler`
- `typescript`

### 当前采用
- `drizzle-orm`
- `drizzle-kit`
- `zod`
- `hono`

## 六、HTTP 请求方案
- 使用原生 `fetch`
- 不使用 `axios`

## 七、数据库落库方案

### 1. `stablecoins`
- 保存稳定币基础字段
- 复杂结构以 JSON 字符串落库：
  - `chains`
  - `circulating`
  - `chainCirculating`

### 2. `stablecoin_metrics`
- 保存稳定币时间快照与补充标识字段：
  - `stablecoin_id`
  - `gecko_id`
  - `circulatingPrevDay`
  - `circulatingPrevWeek`
  - `circulatingPrevMonth`

### 3. `stablecoin_chains`
- 保存稳定币在链维度上的分布数据
- 当前字段：
  - `stablecoin_id`
  - `stablecoin_symbol`
  - `chain`
  - `current`
  - `circulatingPrevDay`
  - `circulatingPrevWeek`
  - `circulatingPrevMonth`

### 4. `yield_pools`
- 保存：
  - `pool`
  - `project`
  - `chain`
  - `symbol`
  - `apy`
  - `tvlUsd`
  - `poolMeta`
- `pool` 作为主键

### 5. `sync_state`
- 记录最近同步时间
- 当前至少包含：
  - `stablecoins:lastSyncAt`
  - `yieldPools:lastSyncAt`
- 当前还记录同步生命周期状态：
  - `sync:lastAttemptAt`
  - `sync:lastSuccessAt`
  - `sync:lastFailureAt`
  - `sync:lastStatus`
  - `sync:lastError`
  - `sync:lastDurationMs`

## 八、当前已实现 API

### 1. `GET /api/health`
- 返回服务健康状态
- 返回最近一次稳定币与收益池同步时间
- 返回最近一次同步的尝试/成功/失败状态、耗时与错误摘要
- 返回当前 D1 中的记录数摘要

### 2. `GET /api/stablecoins`
- 默认按 `circulating.peggedUSD` 降序返回前 `20` 条
- 支持参数：
  - `limit`
  - `symbol`
  - `id`
  - `pegType`
- 返回时会把以下 JSON 字段解析回对象：
  - `chains`
  - `circulating`
  - `circulatingPrevDay`
  - `circulatingPrevWeek`
  - `circulatingPrevMonth`
  - `chainCirculating`

### 3. `GET /api/stablecoins/:id`
- 返回单个稳定币详情
- 同时返回该稳定币的链维度数据

### 4. `GET /api/stablecoin-chains`
- 默认按 `current.peggedUSD` 降序返回前 `20` 条
- 支持参数：
  - `limit`
  - `stablecoinId`
  - `symbol`
  - `chain`
- 用于支撑稳定币的链维度展示

### 5. `GET /api/chains/:chain/stablecoins`
- 返回某条链上的稳定币列表
- 默认按 `current.peggedUSD` 降序返回前 `20` 条

### 6. `GET /api/pools`
- 默认按 `apy` 降序返回前 `20` 条
- 支持参数：
  - `limit`
  - `symbol`
  - `chain`
  - `project`

### 7. `GET /api/sync`
- 用于浏览器直接访问时查看同步入口说明
- 不执行实际同步

### 8. `POST /api/sync`
- 手动触发一次全量同步
- 同步前清空目标表，再写入最新数据
- 成功后更新 `sync_state`

### 9. `scheduled`
- Cron 触发时执行与 `POST /api/sync` 相同的全量同步逻辑

## 九、同步策略
- 第一阶段采用全量覆盖写入。
- 同步顺序：
  - 拉取 stablecoins
  - 拉取 yield pools
  - 清空旧数据
  - 写入新数据
  - 更新同步状态
- 为避免 D1 批量写入过大，当前实现按分块写入。
- 每次同步还会记录尝试时间、成功时间、失败时间、耗时和错误摘要。
- 同步失败时直接返回错误，不做复杂重试、分片同步或部分回滚。

## 十、当前阶段结论
- 第一阶段后端只覆盖 DefiLlama 第一波数据接入。
- 当前实现与文档保持一致：
  - `Workers`
  - `Cron`
  - `D1`
  - `fetch`
  - `drizzle`
  - `zod`
- 后续如果增加 CeFi、缓存、告警、订阅、多数据源聚合，再补新的阶段文档。
