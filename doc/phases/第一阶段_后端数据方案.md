# 第一阶段后端数据方案

## 1. 目标

第一阶段后端目标是支撑当前 MVP：

- 提供稳定币主数据
- 提供相关 DeFi pools 数据
- 提供轻量 CeFi 收益数据
- 提供统一 API 给 Flutter App 使用

当前技术链路：

`DefiLlama / Exchange APIs -> Cloudflare Worker -> D1 -> App API`

## 2. 当前数据源

### 2.1 DeFi 数据

- Provider：`DefiLlama`
- 地址：
  - `https://stablecoins.llama.fi/stablecoins`
  - `https://yields.llama.fi/pools`

### 2.2 CeFi 数据

当前接入两家：

- `Binance`
- `OKX`

当前 CeFi 只保留面向列表展示的核心字段，不做完整交易所产品建模。

## 3. 当前数据范围策略

### 3.1 稳定币范围

Worker 在同步 DefiLlama 稳定币数据时：

- 按 `circulating.peggedUSD` 降序排序
- 只保留前 `20` 个稳定币

这 `20` 个稳定币构成当前系统的 `tracked stablecoin set`。

### 3.2 DeFi pools 范围

Worker 在同步 `yield pools` 时：

- 只保留与这前 `20` 个稳定币相关的池子
- 不再保存与当前 tracked set 无关的池子

### 3.3 CeFi 范围

当前 CeFi 数据仅覆盖：

- `Binance`
- `OKX`

当前 CeFi 列表仅保留这 6 个字段：

- `exchange`
- `assetSymbol`
- `apr`
- `productType`
- `termDays`
- `status`

## 4. 当前数据库表

### 4.1 `stablecoins`

保存稳定币基础信息。当前只保存前 `20` 个稳定币。

### 4.2 `stablecoin_metrics`

保存稳定币相关指标快照。当前只保存前 `20` 个稳定币对应数据。

### 4.3 `stablecoin_chains`

保存稳定币链维度分布。当前只保存前 `20` 个稳定币对应数据。

### 4.4 `yield_pools`

保存与 tracked stablecoin set 相关的 `DeFi pools`。

### 4.5 `cefi_products`

保存 Binance / OKX 的 CeFi 列表数据。

### 4.6 `sync_state`

保存同步状态：

- `stablecoins:lastSyncAt`
- `yieldPools:lastSyncAt`
- `cefi:lastSyncAt`
- `sync:lastAttemptAt`
- `sync:lastSuccessAt`
- `sync:lastFailureAt`
- `sync:lastStatus`
- `sync:lastError`
- `sync:lastDurationMs`

## 5. 当前 API

- `GET /api/health`
- `GET /api/stablecoins`
- `GET /api/stablecoins/:id`
- `GET /api/stablecoin-chains`
- `GET /api/chains/:chain/stablecoins`
- `GET /api/pools`
- `GET /api/cefi-products`
- `GET /api/sync`
- `POST /api/sync`

## 6. 当前同步策略

### 6.1 DefiLlama 同步

同步顺序：

1. 拉取稳定币列表
2. 按 `circulating.peggedUSD` 排序
3. 只保留前 `20`
4. 生成对应的 metrics 和 chain 数据
5. 拉取 `yield pools`
6. 只保留与 tracked stablecoin set 相关的池子
7. 覆盖写入 D1
8. 全部成功后统一写对应 `lastSyncAt`

### 6.2 CeFi 同步

同步顺序：

1. 拉取 Binance 数据
2. 拉取 OKX 数据
3. 规范化为统一字段
4. 覆盖写入 `cefi_products`

### 6.3 运行方式

- 支持 Cron 自动同步
- 支持手动触发同步
- Defi 和 CeFi 已拆成独立 cron 节奏
- 同步过程记录状态、错误和耗时

## 7. 当前阶段结论

第一阶段后端已经从“原始接入”收口到“当前 MVP 真实数据层”：

- DeFi：前 `20` 稳定币相关数据
- CeFi：`Binance + OKX`
- App：统一读取 Worker API

后续如果产品扩展，再进入下一阶段：

- 钱包或合约相关后端能力
- 更强的 Alerts 触发能力
- 更多 CeFi 来源或更深字段
