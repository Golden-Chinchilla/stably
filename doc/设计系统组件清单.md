# Stably 设计系统组件清单

## 1. 目标

这份文档用于收敛当前 Flutter 工程中的设计系统组件、职责边界和使用规范，避免页面继续各自拼装样式。

当前设计系统遵循：

- 风格基线：`Playful Minimalism & Quiet Luxury`
- 品牌气质：克制的 DeFi 高级感
- 工程目标：`MaterialApp` 打底，业务 UI 通过共享组件统一

---

## 2. 分层结构

设计系统分为 4 层：

### 2.1 Token 层

目录：`lib/shared/design/`

- `app_theme_tokens.dart`
  - 颜色 Token
  - 包含 light / dark 两套语义色
- `app_text_styles.dart`
  - 标题 / 正文 / 数字字体体系
- `app_spacing.dart`
  - 间距、圆角、边框宽度等几何 Token

### 2.2 Primitive 层

最小视觉原子，不带具体业务语义。

- `base_card.dart`
  - 所有卡片类组件的基础容器
  - 默认使用 1px border，而不是重阴影
- `metric_text.dart`
  - 数值、金额、APY 等等宽数字文本
- `app_icon_badge.dart`
  - 统一图标容器
- `status_tag.dart`
  - 语义标签基础组件

### 2.3 Pattern 层

可复用的交互 / 状态 / 布局模式。

- `app_interactive_card.dart`
  - 统一卡片点击命中区域与反馈
- `app_filter_chip.dart`
  - 统一筛选 chip / 轻量标签按钮
- `pill_button.dart`
  - 统一主次按钮
- `app_skeleton.dart`
  - 全站 loading skeleton
- `app_empty_state.dart`
  - 全站 empty state
- `async_section_state.dart`
  - 全站错误态与通用 section 级 loading/error 容器
- `app_page_scaffold.dart`
  - 页面头部、滚动区、下拉刷新
- `app_shell_scaffold.dart`
  - 整体 shell、底部导航

### 2.4 Business UI 层

已经具备强业务语义的展示组件。

- `highlight_panel.dart`
  - Hero / Summary 面板
- `insight_tile.dart`
  - 指标卡
- `info_list_card.dart`
  - 属性列表 / 说明列表
- `opportunity_card.dart`
  - 收益池 / 机会卡
- `placeholder_metric_card.dart`
  - 单块关键指标卡
- `allocation_split_card.dart`
  - 分配结果卡
- `alert_rule_card.dart`
  - 告警规则卡
- `risk_notice_card.dart`
  - 风险提示卡
- `section_block.dart`
  - 页面 section 标题 + 内容容器

## 3. 使用规范

### 3.1 不允许直接散写卡片样式

禁止在 feature 页面里直接重复写：

- `BoxDecoration`
- 自定义 border radius
- 自定义 1px border

卡片类 UI 必须优先复用：

- `BaseCard`
- `AppInteractiveCard`

### 3.2 不允许直接散写筛选标签

页面中的可点击标签、筛选项、轻量选择态，优先使用：

- `AppFilterChip`

仅在纯静态语义标记场景下使用：

- `StatusTag`

也就是说：

- `StatusTag` = 展示状态
- `AppFilterChip` = 用户交互入口

### 3.3 数值统一使用等宽数字

以下内容必须优先使用 `MetricText` 或其封装：

- 金额
- APY
- 资产规模
- 持仓数据
- 统计指标

页面中不要直接用普通 `Text` 展示核心财务数字，除非只是次级说明。

### 3.4 页面状态统一

#### Loading

优先使用：

- `AppHighlightPanelSkeleton`
- `AppInsightTileSkeleton`
- `AppInfoListSkeleton`
- `AppOpportunityCardSkeleton`
- `AppMetricCardSkeleton`
- `AppListSkeleton`

不再优先使用 spinner 风格 loading。

#### Empty

统一使用：

- `AppEmptyState`

禁止把“空数据”伪装成“错误态”。

#### Error

统一使用：

- `AsyncSectionState.error`

并通过：

- `AsyncSectionState.presentError`

做错误文案收口。

### 3.5 页面刷新统一

页面级刷新统一走：

- `AppPageScaffold.onRefresh`

页面内部不要自行重复造下拉刷新容器。

### 3.6 列表交互统一

可点击卡片统一走：

- `AppInteractiveCard`

这样可以统一：

- 点击反馈
- 圆角命中区域
- 水波纹行为

## 4. 当前推荐组件映射

### 4.1 首页 / Discover / Detail Hero

使用：

- `HighlightPanel`

loading 使用：

- `AppHighlightPanelSkeleton`

### 4.2 指标网格

使用：

- `InsightTile`

loading 使用：

- `AppInsightTileSkeleton`

### 4.3 机会 / 收益池列表

使用：

- `OpportunityCard`

loading 使用：

- `AppListSkeleton`

### 4.4 稳定币筛选与链筛选

使用：

- `AppFilterChip`

### 4.5 稳定币属性 / 规模趋势

使用：

- `InfoListCard`

loading 使用：

- `AppInfoListSkeleton`

### 4.6 空页面 / 空 section

使用：

- `AppEmptyState`

### 4.7 错误 section

使用：

- `AsyncSectionState.error`

## 5. 页面接入建议

后续新页面开发时，优先顺序如下：

1. 先用 `SectionBlock` 组织信息层级
2. 再选择对应业务组件
3. 如果没有合适组件，先判断是否应补到设计系统，而不是直接在页面里散写

推荐判断标准：

- 如果同类 UI 会在两个以上页面复用，应优先沉淀到 `lib/shared/widgets/`
- 如果只是单页特有、且业务语义很重，可以先放在 feature 内部

## 7. 后续收敛方向

下一轮建议继续收敛：

- 输入类组件
  - `AppTextField`
  - `AmountInput`
  - `SearchInput`
- 选择类组件
  - `SegmentedControl`
  - `BottomSheetPicker`
- 反馈类组件
  - `Toast`
  - `Banner`
  - `InlineNotice`
- 数据展示类组件
  - `StablecoinCard`
  - `ChainDistributionCard`
  - `PoolSummaryCard`

这会让后续 feature 页面基本不再直接写零散样式。
